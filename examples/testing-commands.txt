RUN FROM YOUR ODIN PROJECT FOLDER

MAC - TERMINAL 1 (leave the server running)

source .venv/bin/activate
python -m uvicorn app:app --host 127.0.0.1 --port 8000

MAC - TERMINAL 2 (same folder)

source .venv/bin/activate
curl -sS -i -X POST http://127.0.0.1:8000/send -H 'Content-Type: application/json' -d '{"recipient":"demo-user","message":"Hello"}'
python -m pytest -v

Repeat the curl command to get another random result. The HTTP status line and
JSON body are both displayed. Do not add --fail: it hides error response bodies
on some curl versions. An HTTP 400/429/500/503 can be a valid simulated outcome.

WINDOWS POWERSHELL - STUDY EXAMPLE

Open the local Desktop folder '1 - Example Code' in VS Code. In its Terminal:

python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m uvicorn app:app --host 127.0.0.1 --port 8000

In a second PowerShell Terminal in that same folder:

.\.venv\Scripts\python.exe -c "import httpx; r = httpx.post('http://127.0.0.1:8000/send', json={'recipient':'demo-user','message':'Hello'}); print('HTTP status:', r.status_code); print(r.text)"
.\.venv\Scripts\python.exe -m pytest -v

No command above saves results to files. The tests control random statuses to
check every path reliably. No real messages or LLM calls are made.
